## v1.3.1（2026-10-09）：游客须先点选进入群聊才能发言

- **安全**：游客此前一进站就被服务端默认放进列表第一个群（`boot.room` 恒为首个房间），
  于是一个群都没点也能直接发言。现在游客默认不进入任何群，必须先点选一个群
  （或走 `?room=ID` 直达）才解锁输入区。
  - 服务端 `renderChat()`：游客且非 URL 直连时下发 `room=0`，顶栏房间名显示「请选择一个群聊」
  - 前端 `OwChat.init()`：`room=0` 时不发 `room_join`/`history`、不拉轮询，输入区走新闸门 `'room'`
  - 前端 `switchRoom()`：游客点选即视为已进入，立即解锁输入区（不等 `room_members` 异步返回）
  - 服务端 `Chat::send()`：游客发言前校验 `online` 心跳（该 guest 在本群有 ≤120 秒内的心跳），
    构造请求直接打 `send` 没有心跳记录，同样被拦（提示「请先进入该群聊后再发言」）
  - 顶栏「可发言」标签随闸门联动隐藏，不再出现「禁着言却写着可发言」的自相矛盾
- 注册用户不受影响：仍按 v1.2.27「先加入才能发言」约束，`boot.room` 照旧是首个房间。

## v1.3.2（2026-10-09）：修复敏感词后台页打开即卡死

- **修复**：`plugins/sensitive-words/admin.js` 的 MutationObserver 回调只判「表格是空行」就 `init()`，
  没有防重入标记 —— 而 `OwSW.init()` 里的 `OwAdmin.uiBatchBar()` 会同步写 `#owSWBatch` 的 innerHTML，
  这次 DOM 改动立刻再次触发观察者；此时列表 XHR 还没回来、表格仍是 0 行，于是 `init()` 被无限递归
  调用（每轮还多打一个列表请求），主线程 100% 占满，表现就是一进页面浏览器直接卡死。
  改为把标记挂在表格元素上（`t._inited`），与 content-report / announcements 两个插件的写法一致；
  标记随元素走，切走再切回时表格是新元素，仍能正常重新初始化。
- 用最小 DOM 模拟（stub MutationObserver + uiBatchBar 写 DOM）实测：修复前 300ms 内 init 已执行
  22 次且持续增长，修复后稳定 1 次、列表请求 1 次。

## v1.3.5（2026-10-09）：修复会话被销毁后登录页 500（「一开 F12 就掉登录」）

- **修复**：登录 / 注册 / 找回密码页直接读 `$_SESSION['anon_key']` 传给 `Sec::signField()`。
  会话一旦被指纹守卫销毁（或被 GC 回收、php-cgi 多进程丢失重建），`$_SESSION` 被清空，
  该值变成 null → `Sec::signField(): Argument #1 must be of type string, null given` →
  **整页 500**，同时用户表现为「打开开发者工具后掉登录、页面报错」。
  - 新增 `Sec::anonKey()`：按「会话 → cookie 备份 → 新生成」兜底并回写，
    与 `verifySignAny()` 的双密钥口径一致（会话密钥 + cookie 备份），保证签名链路不断
  - `renderAuth()` 的 login / register / reset 签名与 `OwAuth.init` 下发的 key 全部改用它
- **修复**：指纹守卫在**拿不到 UA** 时不再比对、不再销毁会话。
  `fingerprint()` 默认只绑 UA，UA 缺失会算出与存档必然不等的指纹，
  于是「没有 UA 的请求」被当成 Cookie 重放而销毁正常会话（探测类 / 工具请求的典型特征）。
  拿不到 UA 时指纹本身不可信，放行比误杀更安全。
- **改进**：真正销毁会话时**无条件**写一条 `data/fp_trace.log`（原先只有 `sec_fp_trace=1`
  才写，而该开关默认关闭，等于「掉登录」时永远没有现场证据）。只在 mismatch 时写，量极小。

## v1.2.13（2026-10-04）：图片与附件取消白色底座

- **改进**：`type=image` / `type=file` 消息不再套 `.ow-msg-content` 气泡，
  改用新的无气泡容器 `.ow-msg-plain`。
  v1.2.7 把气泡底改成纯白后，这两种消息就多了一层「白底座」——
  文件卡片自身已有 `background + border`，套上白气泡后呈现为
  **白底里再套一个白框**，视觉上像双重边框，很脏。
  图片同理：白底托着一张图，多余的白色边框毫无意义
- **新增**：`.ow-msg-plain` —— 透明底容器，靠三点保证观感不塌：
  1. `overflow:hidden` —— 让 `.ow-msg-img` 的圆角对容器裁切生效，不露方形硬角
  2. `line-height:0` —— 消除 inline 元素基线间隙，避免图片下方多出几像素空白
  3. `display:inline-block` —— 让 `overflow` 裁切与圆角生效
  图片与文件卡片**自身外观本就完整**（`.ow-msg-img` 有圆角、`.ow-file-card` 有白底+边框），
  故不需要任何额外装饰

- **修复**：**图片 / 文件消息撤回时占位文案不显示**。
  `markRecalled()` 原先只查 `.ow-msg-content`，去掉气泡后 `cs` 为 null →
  `outerHTML` 替换整段不执行，表现为「点击撤回后界面毫无变化、原图/文件仍在」。
  现同时查 `.ow-msg-plain`，替换后统一回退为 `.ow-msg-content`，
  使 `.ow-msg.recalled` 的虚线弱化样式正常生效

⚠️ 刻意**没有**选择「给 `.ow-msg-content` 加个 class 再用 CSS 覆盖」的做法：
该类节点还需参与 `markRecalled` 的 `outerHTML` 替换与 `jumpToQuote` 的
`querySelector('.ow-msg-content')`，多一层节点反而更脆；直接去掉节点最干净。
留空 span 也不行——会破坏 flex 基线对齐。

文字类消息（text / mention / system / recalled / deleted）**保持原气泡不变**。

验证：真实 Chrome 断言 20 项全通过。覆盖双方图片/文件均无 `.ow-msg-content`
（`hasBubble=false`）且改用 `.ow-msg-plain`、容器背景为 `rgba(0,0,0,0)`、
`line-height:0px`、`overflow:hidden`、图片圆角 6px 保留、
文件卡片自身仍为 `rgb(255,255,255)` 白底（无双层白框）、文字消息未被误伤；
**以及本次修掉的撤回 bug**：图片/文件撤回后 `recalled` 类正确添加、
占位文案「此消息已撤回」正常渲染、原图与原文件卡片均已移除、
占位态为透明底 + `dashed` 虚线边框 + 副文本色。
截图确认文件卡片已变为单层白底+边框。

## v1.2.12（2026-10-04）：群聊昵称色 → #8E8EA0（首次达到 WCAG 达标）

- **改进**：`.ow-msg-meta .ow-msg-nick` 由 `#CCCCCC` 改为 **`#8E8EA0`**。
  **对比度 3.22:1（白底）/ 2.95:1（消息区底），首次跨过 WCAG 非文本元素
  3:1 的门槛** —— 此前六轮调色（#333333→#999999→#E4E4E4→#D5D5D5→#E8E8E8→#CCCCCC）
  全都低于 3:1，属「刻意弱化」区间，本版起是**真正达标**的取值

- **附带优势**：该色带 **11% 蓝紫饱和度**，在纯灰/白背景上比同亮度的纯灰
  更易辨识（人眼对有色相的浅色比对中性灰更敏感），观感是「有颜色但不抢眼」。
  色相与品牌主色 `--ow-primary`(#00A0E9 蓝系) 一致；
  hover 态的 `--ow-primary-dark`(#00558F 深蓝) 也能自然衔接

## v1.2.4（2026-10-04）：删除 / 撤回语义彻底对调

**这是本项目最容易搞混的一处语义，v1.1.x 的口径与现在完全相反，勿回退。**

| 操作 | 作用范围 | 谁可以 | 实现 |
| --- | --- | --- | --- |
| **删除** | **仅本机隐藏**，别人照常看得到，换设备不生效 | **任何身份**（含超管、群主） | 写 `message_hides` |
| **撤回** | **全局生效**，所有人都不再看到 | 自己 5 分钟内 / 群主 / 超管 | **物理 DELETE** 行 + 删附件 |

- **修复**：「删除」此前对管理员 / 群主 / 作者本人是**全局真删除**（清空正文 + 留行审计），
  只有其他人才降级为本机隐藏。现改为**一律只在本机隐藏**——**包括超级管理员**，
  任何人都不再能用「删除」让内容对别人消失
- **重构**：真正让内容全局消失的唯一入口是「撤回」，改为**物理 DELETE 行 + 立即删附件**，
  不可恢复。前端撤回成功后直接移除气泡，不再走软删除时代的 `markRecalled` 占位
- **改进**：两条确认框文案彻底分离，避免用户误判：
  - 删除 → 「删除后仅本机不再看到，其他人不受影响」
  - 撤回 → 「撤回后所有群成员都不再显示，且不可恢复」+ 补一句「如只想自己不看，请用删除」
- **移除**：右键菜单的删除入口**不再判权限**（原先无权用户那档才给「删除」），
  所有已登录用户一律可见——它只是「我不想看这条」的私人视图行为，不涉及他人
- **移除**：`messages.keep_forever` 免清理标记随撤回改为物理删除而下线，
  `purgeExpired()` 不再有该条件。存量列保留不删，**勿重新启用**
- **移除**：`messages.deleted` 软删除路径不再写入新数据（`pack()` 仍读它以兼容存量行）

为什么这样切分：撤回是**有节制**的——有时间窗、有角色限制、内容对称（你也撤不了我的）；
删除是**无节制**的，任何人都能点。若让删除也全局生效，等于把「清空整个群聊」的决定权
交给每个用户。**超管在前台同样不例外**：清除他人内容只有撤回一条路。

代价与取舍：撤回改为立即物理删除意味着**没有审计留痕**（谁撤的、何时查不到）。
这是刻意的——撤回语义就是「这段话不该存在过」，留行反而是负担。
关键操作仍在 `security_logs` 留一条 `msg_recall` 供事后追溯。

验证：端到端 38 项断言全通过（真实库零污染）。覆盖超管删他人消息仅本机生效、
消息行仍在库/正文未清空/deleted 仍为 0、隐藏行幂等、hiddenIds 只影响本人视图、
撤回物理删行、4 分钟可撤/6 分钟拒、撤回附件即删、路径穿越防护、
超管不得撤回他人私聊但自己发的仍放行，以及两条确认框文案的正反核对。

### v1.1.0 第二批（2026-10-03）：合规查阅、软删除、游客发言间隔

- **新增**：插件 `dm-compliance`（私聊合规查阅）——经 `dm.read` 钩子为**超级管理员**开一个显式合规查阅入口，按用户 ID + 时间范围检索其参与的全部私聊，满足《个人信息保护法》第 35 条、GDPR 合法利益例外等「有合法权限时须可调取」的法规要求
- **安全**：合规查阅**默认关闭 + 强制留痕**——插件未注册 `dm.read` 钩子时物理上无法查阅（停用即失效）；`role` 必须为 `admin`，member 与游客一律拒绝；无论命中与否都写 `security_logs`（合规答复需举证「查过但没有」）；核心与插件各校验一次（纵深防御）；全程只读，不提供任何写路径
- **安全**：核心 `dm-privacy` 硬约束（私聊仅双方可见，管理员亦不例外）**未被放开**——新增的 `Chat::dmComplianceRead()` 是唯一能绕过 `visible()` 的入口，其余路径一律不变
- **重构**：消息删除**全量改为软删除**（含超级管理员）——行保留、`content` 与 `quote` 清空（原文不可恢复），昵称 / 时间 / IP 等元数据留存以备审计；不设「超管绕过保留期」的旁路，任何人都无法提前物理清除
- **新增**：系统设置「已删除消息保留期(天)」，默认 30 天，0 表示永久保留；到期后由 `Chat::purgeDeleted()` 统一物理清除（读消息时顺带触发，小时级节流，失败静默不影响主流程）
- **改进**：`messages` 表新增 `deleted` / `deleted_at` / `deleted_by` 三列（幂等迁移），前台按 `deleted` 标记显示「该消息已删除」虚线占位，与撤回文案区分
- **新增**：系统设置「游客发言间隔(秒)」，默认 30，**取代**原「游客每日发言限额」；复用 `rate_limits` 表（`bucket=guest_gap`）实现，不新增表结构；0 表示不限制，登录用户不受影响
- **移除**：`guest_daily_limit` 默认值下线，`ensureGuest()` 不再写 `daily_count` / `daily_date`（`guests` 表列保留不动，规避 SQLite 删列重建风险）
- **改进**：消息时间不再紧贴头像远端，改为**紧跟昵称**；且仅在鼠标悬停消息气泡**满 2 秒**后才显示，移开立即隐藏并清理计时器（CSS `:hover` 无法表达「持续满 N 秒」）
- **改进**：自己的消息整行镜像（`row-reverse`）时用 `order:-1` 把时间拉回昵称**右侧**，避免时间被甩到昵称左边
- **修复**：游客身份不再出现头像右键菜单的「禁言」项——`BM.canBan()` 改为显式判 `actor.kind === 'user'`，不再依赖「`cfg.me` 为 null 时 `me.id` 抛异常被 `try/catch` 吞掉」这种顺带成立的副作用
- **改进**：私聊消息气泡与群聊**完全一致**——移除 `.ow-msg.private` 的独立紫色配色与 `::after` 追加的「[私信]」标签
- **安全**：`quote` 列存在 `NOT NULL` 历史约束，软删除时写空串而非 `NULL`（否则触发 SQL 完整性错误）
- **修复**：`dmComplianceRead()` 在 `Plugin` 类未加载的精简部署（如 CLI 批处理）下会 fatal error——补 `class_exists('Plugin')` 防御，此时合规能力应「不可用」而非崩溃
